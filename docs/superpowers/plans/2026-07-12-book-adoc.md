# `--book` Single-File Book Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in `--book` flag (CLI) and a "Generate book.adoc" checkbox (GUI) that assemble the archive into a single `book.adoc` at the archive root, using `include::<page>.adoc[leveloffset=+1]` for `index.adoc` and every archived post.

**Architecture:** A new `Archive::write_book` writer (sibling of `write_index`) emits a fixed `:doctype: book` + `:toc:` header followed by `include::` directives. `run.rs` calls it after `write_index`, gated on a new `RunOptions::generate_book` flag, in both the single-post and journal paths. The CLI and GUI each set that flag. No changes to discovery, fetching, parsing, media, or the AsciiDoc renderer.

**Tech Stack:** Rust 2024, clap (CLI), iced 0.14 (GUI), tokio, wiremock + assert_cmd (integration tests), tempfile.

**Design spec:** `docs/superpowers/specs/2026-07-12-book-adoc-design.md`

## Global Constraints

- **Edition 2024; workspace version stays `1.0.0`** — this is not a release; do not bump `Cargo.toml` version.
- **No new dependencies.** Everything needed is already in the workspace.
- **Format (CI-enforced, exact):** `cargo fmt --all --check -- --config=imports_granularity=Crate`. There is no `rustfmt.toml`, so the `--config=imports_granularity=Crate` flag is required; plain `cargo fmt` fails CI. Run `cargo fmt --all -- --config=imports_granularity=Crate` (no `--check`) to format in place before committing.
- **Lint:** `cargo clippy --all-targets --all-features -- -D warnings`.
- **Test:** `cargo test`.
- **`Cargo.lock` is gitignored** — never `git add` it.
- **Tests must not hit LiveJournal.** Use local `wiremock` mock servers (integration) and `tempfile` dirs; assert against them only.
- **Keep the README in sync with behavior in the same change** (project rule).
- **Do not touch the AsciiDoc renderer (`src/adoc/`) or any per-post output.** `book.adoc` only adds `include::` directives; post files are unchanged.
- **`book.adoc` byte format is fixed** (see spec). Unit tests assert the exact bytes; the file ends with exactly one `\n`.

```rust
    pub fn write_book(&self, posts: &[ArchivedPost]) -> Result<PathBuf> {
        fs::create_dir_all(&self.root).map_err(|source| LjError::Write {
            path: self.root.clone(),
            source,
        })?;
        let mut contents = format!("= {} Archive\n:doctype: book\n:toc:\n\n", self.journal);
        contents.push_str("include::index.adoc[leveloffset=+1]\n");
        for post in posts {
            let path = self.index_path(&post.path);
            contents.push_str(&format!(
                "\ninclude::{}[leveloffset=+1]\n",
                path.to_string_lossy()
            ));
        }
        let path = self.root.join("book.adoc");
        write_atomic(&path, &contents)?;
        Ok(path)
    }
```
